# VJVisionFX：音乐节奏驱动的背景纹理系统 - 产品需求文档

## Overview
- **Summary**：把 VJVision fork 为一个独立新项目 **VJVisionFX**（独立目录 + 独立 git 新仓库），并将可视化窗口的背景从"缓慢环境漂移的流动波场"升级为**由音乐节奏实时生成的生成式纹理系统**——可视化子进程直接从 48 段频谱 + 峰值实时提取低频/节拍/能量特征，驱动多套可在控制台切换的背景纹理。
- **Purpose**：让背景不再是静态氛围，而是跟随鼓点/低音/能量律动的"视觉乐器"，强化 DJ 现场的氛围表现力；以独立分支项目的形式自由迭代新纹理，不影响稳定的 VJVision 主线。
- **Target Users**：本项目作者/现场 VJ（Windows 单机、USB 便携使用）。

## Goals
- 建立独立的 VJVisionFX 项目（自有 git 仓库、独立品牌与版本）。
- **纯视觉方向**：工作集中在视觉效果。**移除音乐分析/识别**（dejavu 指纹、曲库索引、曲目识别、专辑封面匹配、分析/曲库 UI）；仅保留音频采集（输入设备/回采 → 实时频谱与电平）作为视觉驱动信号。
- 在可视化端实现实时**节奏特征提取**：低频包络、节拍/onset 脉冲、中频/高频能量、整体能量，直接从采集频谱推算，不依赖识别结果、不新增进程。
- 提供**纹理框架 + 多套可切换纹理**（首版 ≥3 套，观感明显不同），在控制台实时切换并持久化。
- 画面只有**两层**：节奏生成的背景纹理 + 全程顶层叠层。不绘制频谱（bar/wave/mirror）、旋转封面、歌名文字，也没有待机淡入淡出。
- 顶层叠层**全程显示**：贯穿整场、最上层、居中、最大边 ≤40% 屏、不放大、保留 alpha；支持带 alpha 视频（WebM 等）与动图（WebP/APNG/GIF），用现有 ffmpeg 逐帧解码 RGBA 循环播放；静态图照旧；无 ffmpeg 回退首帧/静态。
- 纹理配色脱离封面：内置默认调色板，并可在设置叠层素材后从素材提取主色调染色。
- 无音频/静音时纹理保持轻柔待机运动（不黑、不冻结、不崩溃）。

## Non-Goals
- **不做任何音乐识别/分析/曲库功能**：不运行 dejavu、不连 MySQL/SQLite 指纹库、不做曲目匹配与封面匹配、不显示分析/曲库 UI（相关代码可不物理删除但不被调用/不展示）。
- 保留音频采集（pyaudiowpatch）与可视化消息管线，因为视觉要靠实时频谱驱动。
- 不做跨进程的高精度节拍检测（节拍一律在可视化端从频谱轻量推算）。
- 本次不做多套纹理之外的新交互（如 MIDI、外部同步、视频导出、着色器自定义编辑器）——后续迭代再加。
- 本次不创建 GitHub 远程仓库、不发布 Release（本地 init + 首次提交；推送/发布需用户显式要求）。
- 不重写 GPU/vsync 渲染底座（沿用现有 D3D11/SDL2 Renderer 与 bilinear 上采样路径）。

## Background & Context
- 现有"波纹纹理"= `vjvision/visualizer.py::_make_flowing_bg`：320px(GPU)/160px 低分辨率 numpy 波场，每 3 帧重绘一次后 bilinear 上采样；5 层 60–100 秒周期的低频正弦叠加，仅以 `amp = 0.25 + 0.12*energy` 与低频能量弱耦合——**不跟节拍**。
- 可视化子进程每帧可得到：`state.bins`（48 段、dB+Mel 平滑后的频谱，0..1）、`state.peak`、帧时间 `dt`、`time.monotonic()`。背景色取自封面主色 `rs["dominant_colors"]`。
- 背景现由 `SETTINGS.visual.bg_mode`（"flow"/"blur"）控制；UI 下拉在 `debug_ui.py`（392–399、719–721 行），配置在 `config.py`（115 行 `bg_mode`），通过 `{"type":"settings",...}` 消息下发可视化进程。
- 用户已确认：① 独立新目录/新仓库；② 名称 **VJVisionFX**；③ 首版即**多套可切换纹理**；④ 节拍由可视化端从频谱实时算。
- 借鉴经验：把"节奏纹理"做成跨风格的独立背景渲染层，新增纹理不得移除/遮蔽前景核心元素；新增配色统一使用既有主色调色板，避免平行命名导致的取色 undefined。

## Functional Requirements
- **FR-1（项目分叉）**：在 `c:\Users\jason\Documents\trae_projects\VJVisionFX` 生成独立项目——仅复制源码与配置（不含原 `.git`、`cache/`、`dist/`、`build/`、`*.log`、`__pycache__`），在新目录 `git init` 并做首次提交；品牌改为 VJVisionFX（窗口标题、README 主标题），版本线改为 FX 系列 `0.1.0-beta`。
- **FR-2（节奏特征提取）**：在 FX 项目可视化端新增轻量特征提取器，每帧从 `bins`+`peak`+`dt` 计算：低频(bass)能量、中/高频能量、整体能量、以及基于低频能量通量的自适应 onset/节拍脉冲（触发后快速衰减形成 beat envelope）。静音/无数组时输出平滑的空闲值。该逻辑为纯函数/可独立单测。
- **FR-3（纹理框架）**：新增纹理框架：注册制命理纹理；每个纹理接收（调色板、屏宽高、时间、节奏特征、各自持久状态）输出一张低分辨率 RGB 小图（复用现有 GPU bilinear 上采样；软件路径同步可用）；约 20fps 节奏重绘，单帧预算与现有波场相当；统一施加暗化/晕影以保证前景可读；无音频时进入轻柔待机运动。
- **FR-4（首版 ≥3 套纹理）**：提供至少三套观感明显不同、均受节奏驱动的纹理：
  1. **律动波场 pulse**：现有流动波场的节奏化演化——节拍脉冲放大振幅/湍流并产生径向推挤，整体随拍呼吸。
  2. **同心涟漪 ripple**：低频/节拍触发自焦点向外扩散的叠加圆环（加性、渐隐）；低频=大而慢的环，高频=小而快的细漪。
  3. **粒子迸发 particles**：节拍触发粒子自焦点径向喷发后缓落/漂移，带余辉拖尾；能量决定喷发数量与速度。
- **FR-5（切换与持久化）**：控制台"可视化显示"区提供纹理选择下拉（仅 FX 背景模式下显示/启用），选择通过 `settings` 消息实时下发、无需重启即生效；选择写入 `prefs.json`（如 `fx_texture`），FX 项目默认背景模式为新的 `fx`。
- **FR-6（FX 画面两层化）**：FX 可视化渲染**只**绘制两层：**节奏背景纹理（fx）** + **顶层叠层**。不再绘制前景频谱（bar/wave/mirror）、旋转专辑封面、歌名/专辑文字、待机淡入淡出；**移除基于封面的 blur 背景**（不再有封面可模糊）。
- **FR-7（可观测性）**：纹理切换、叠层加载、素材解码失败、特征异常等有日志；沿用现有 `visualizer.log`，运行不得出现新增错误/异常。
- **FR-8（全程顶层叠层）**：把原待机图升级为**全程叠层**：设置素材后整场都绘制在背景之上的最上层；居中、最大边 ≤40% 屏、不放大、保留 alpha；无素材时仅显示背景纹理；无淡入淡出。
- **FR-9（动态/alpha 素材解码）**：叠层加载器接受静态图（PNG/JPG/BMP/WEBP）、动图（动态 WebP/APNG/GIF）与带 alpha 视频（WebM 为主）。动态/视频用现有 ffmpeg 逐帧解码为 RGBA（透明保留），按素材自带帧率循环播放；解码失败/无 ffmpeg 时回退：静态图直接用，动图/视频用首帧或静态 PNG；内存内缓存帧序列并限制总帧数/分辨率以防爆内存。文件选择对话框放开这些扩展名。
- **FR-10（叠层素材选择/持久化）**：控制台叠层加载支持选择上述动态素材，路径写入 prefs（复用现有 standby image 配置位），重启后恢复并自动循环播放。
- **FR-11（移除音乐分析/识别与相关 UI）**：FX 启动**不连接 dejavu/不连任何指纹数据库/不做曲目与封面识别/不索引曲库**；matcher 仅保留音频采集、实时频谱与电平计算、对可视化子进程的消息/命令管线。控制台**移除分析/曲库/索引相关 UI**（分析队列、强制重新分析、曲库状态、音乐目录、数据库面板等）；保留输入设备选择、电平表、可视化显示（GPU/演示/背景纹理/叠层）控制。代码可保留但不被调用、不展示，保证零识别行为且无 DB 依赖。
- **FR-12（纹理配色来源）**：纹理使用**内置默认调色板**（脱离封面主色）；当用户设置了叠层素材时，从该素材（静态图或动图/视频首帧）提取主色调对纹理染色（复用现有主色提取工具），未设置素材时用默认调色板。

## Non-Functional Requirements
- **NFR-1（性能）**：纹理在低分辨率网格（≤320px 宽）用 numpy 向量化生成，单次重绘目标 ≤ 数 ms（与现有 `_make_flowing_bg` 同量级），维持 ~60 FPS（重绘按 ~20fps 节拍，其余帧用缓存纹理）。
- **NFR-2（零新依赖/零新进程）**：仅用 numpy + pygame（SDL2），不引入新第三方库、不增加子进程。
- **NFR-3（健壮性）**：频谱数组为空/全零/尺寸变化、无音频硬件、软件渲染回退时均不崩溃。
- **NFR-4（便携/兼容）**：保持 USB 单 exe 便携能力与现有 PyInstaller 打包路径；4K/竖屏/全屏自适应沿用现有 layout。
- **NFR-5（中英双语）**：所有新增 UI 文案 zh/en 两套 key 且数量一致。

## Constraints
- **Technical**：Python 3.14 + pygame-ce(SDL2) + numpy；GPU 走 `pygame._sdl2.video.Renderer`/`Texture`，软件走 `screen.blit`；纹理走小图 + bilinear 上采样。
- **Business**：所有发布仍为 beta；FX 线版本从 `0.1.0-beta` 起；不主动推送 GitHub / 打包 / 提交（除新仓库首次本地提交外，后续均需用户显式指令）。
- **Dependencies**：fork 自 VJVision 当前代码（含 v1.2.1-beta 的无音频加固与 ffmpeg 兜底）。

### AC-5：纹理与音乐节奏的视觉同步度
- **Type**: `rubric`
- **Dimension**：节拍反应的可见性与观赏性
- **Scale**: 1-5
- **Anchors**: 1 = 背景与节拍无关或冻结/纯环境漂移（等同现状）；3 = 能量变化有可感响应但与鼓点对不上、纹理区分不明显；5 = 鼓点/低频触发的涟漪/脉冲/迸发清晰可辨且与节拍同步、三套纹理风格差异显著、静音时仍有柔和待机运动且前景清晰可读。
- **Pass Threshold**: >= 4
- **Evidence**：自动化"模拟节拍帧 vs 静音帧"的帧差异度量（节拍帧纹理变化显著大于静音帧）+ 用户人工观看确认。
